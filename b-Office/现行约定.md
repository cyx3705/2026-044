## 公式库取舍

- **名字不走 History + 神名**：模块名、程序集名都是 `Norma`；页面 owner 仍按宿主规则推为 `HistoryNorma`。
- **一条公式一套元数据**：编号、名称、出处条款（GB/ISO/手册页码）、输入输出变量与单位、适用范围、依赖的查表。自描述就从这套元数据生成，不另写说明。✔
- **结构**：`b-Code/Norma/Formulas/` 是纯计算核心（`Calculation` 元数据 + 各类 `All()` + `Catalog`），**不许引用宿主**，将来原样抽成独立 NuGet 包；`NormaCommands` 把每条计算投成一条指令。✔
  - 加一条计算：在对应类的 `All()` 里加一个 `Calculation`；新一类就加一个静态类，再在 `Catalog` 里接上一行。
  - 测试会自动拿示例值跑一遍，但还是要在 `TestReferenceValues` 补一条手算或标准表的对照值。
- **单位全库统一**：长度 mm、力 N、扭矩与弯矩 N·m、应力与模量 MPa、功率 kW、转速 r/min、角度 °、寿命 h 或 10⁶ 转。例外要写在该量的元数据里（如过盈量 μm、公差 μm）。
- **系数的缺省值是粗估值**，例如 K_A 1.25、K_v 1.1。缺省值必须写进参数说明，让调用方知道是估的。查表才能得到的量（X/Y、材料极限、综合影响系数）一律由调用方输入，本库暂不带表。
- **判据只报结论，不拦结果**：不满足时指令照样成功，消息里列出哪条不成立；输入越界或缺参才算失败。
- **全部按公式自行实现**：0.2.0 没有拷贝任何第三方代码，齿轮也是按 ISO 6336 的公式自己写的。
- **0.2.0 的已知简化**：
  - 接触强度只算节点处，未计单对齿啮合系数 Z_B/Z_D；
  - 弯曲强度的 Y_F/Y_S 按方法 B 计算，但只验证了量级，以及齿数、变位对它们的影响方向，还没有对照过标准算例；
  - `fit.it` 给的是公式值，没有按标准规则圆整。
- **来源与许可（2026-11-03 调研）**：开源界和 NuGet 上没有能整体拿来用的机械设计公式库。
  - 齿轮：efirvida/python-gearbox（MIT，ISO 6336:2019 / AGMA 2001）可以移植，须保留署名。
  - pablomarcel/design 没有许可证，mechanical-kit 的数据是 CC BY-NC，二者只当核对样例，不拷代码或表格。
  - VDI 2230 螺栓和 ISO 281 修正寿命没有开源实现，只能按标准原文自己写。

## 标准代号表取舍

- **范围只到两页**：数据只取机械工程师手册 `sjzl` 章第 16 页「国内部分标准代号」和第 17 页「国外部分标准代号」，共 111 条；别的标准号、表格正文一律不进来。标准号→正式名称是后续任务，不在本表里硬凑。
- **只收四样**：代号、名称、国内/国外、页脚注或收录说明。数据在 `b-Code/Norma/Formulas/standards.tsv`，作为嵌入资源随 DLL 发布，部署不依赖外部文件；加条目只改这个 TSV。
- **原文残缺的处理**：手册扫描页有 4 处缺字（JB、NJ、MT 的名称，墨西哥代号），按代号通用写法补齐并在 note 里注明；ICONTEO/ICONTEC、GOST/ГОСТ、CSN/ČSN 保留手册写法并给出通用写法。不能确定的地方宁可在 note 里说明，不静默改数据。
- **两页脚注也是数据**：国内页脚注「代号后加 `/Z` 为指导性技术文件，加 `/T` 为推荐性标准」；国外页脚注「台湾省标准 CNS、南非标准 SABS、以色列标准 SI」，已按条目收入。
- **查表规则**：代号先完全一致、再前缀（`GB/T5782` 会落到 `GB`），名称按完全一致、开头、包含；0 条也算正常结果。页面仍只有公式目录，标准代号走控制台或 MCP 调用。

## 金属强度换算取舍

- **数据范围**：机械工程师手册 `sjzl` 章共 6 张表。钢：高硬度段 HRC/HRA/HR15N/30N/45N/HV/HB + 9 个钢种列 + 不分钢种；低硬度段 HRB/HR15T/30T/45T/HV/HBS + 不分钢种 σb；另有「钢的肖氏与洛氏硬度换算」HS↔HRC。有色：变形铝合金（HB/HV/HRB/HRF/HR15T/30T/45T + 7 个牌号 σb）、黄铜（HB 90–168 与续表 170–210）、铍青铜（续表 170–220 与 288–420）。数据在 `b-Code/Norma/Formulas/metal-*.tsv`，作为嵌入资源随 DLL 发布。
- **三族一个工具**：只注册一条 `norma.metal.strength`，参数 `family`（steel/aluminum/copper）、`scale`（14 种硬度制）、`value`、`grade`（钢种/铝合金牌号/铜合金板材棒材；`auto` 取该族默认）；保留 `steel=` 兼容别名。结果同时给出已定义硬度制、无定义项及原因、选定牌号的 σb（铍青铜另给 σ0.2、σ0.01）。
- **自描述里的组合提示**：`family` 参数直接写「族→可用硬度制」矩阵和默认牌号，`grade` 参数写族牌号列表；AI 不需要先验，也不用先试探再猜。
- **回执只给增量信息**：`hardness` 只列已定义硬度制；`undefined`/`strength_undefined` 只给短范围（如 `60–100`、`55–164`），不再写长句；`source` 只写 `sjzl章`，不重复出处和适用范围全文。测试钉住单次回执小于 700 字符、消息小于 300 字符。
- **拟合方式用 PCHIP，不用多项式**：节点就是原表，节点之间单调保形插值；节点处原样返回，不做外推。用户明确要求「有定义域，没定义的地方千万别猜」，所以每个硬度制、每个牌号列都保留自己的节点范围，超出范围返回「该硬度无定义」及原因。
- **定义域以表为准**：钢 HRC 17～70；HRA 39～70；HR15N/30N/45N 17～65；HB 211～501（HRC 17～51）；HRB/HV 低段 60～100；HBS 60～82；HS 29.6～96.6（HRC 13～68）。铝 HB 55～175，但硬度制只到 HB164。铜低段 HB 90～220、高段 HB 288～420。牌号列各自还有更窄范围（如超高强度钢 39～60、7A04 55～164）。
- **两处源表缺口按无定义处理**：铜表 HB 222～286 原表整段缺行；铝表 HB 165～175 的硬度列整段重复 160～170 的值。按「没证据不猜」，这两段不插值：铜 HB 222～286 直接报缺口；铝 HB 165～175 只输出 a211 的 σb，硬度制不输出。
- **两段靠 HV 搭桥（钢）**：HRB 段与 HRC 段在 HV 211～233 重叠。输入落在哪段就以哪段为主；另一段通过 HV 反解补出可用的硬度制，不覆盖已有值。强度优先用输入所在段，低硬度段的不分钢种直接用低表 σb；指定钢种在低段没有数据时，若经 HV 能落到高段的该钢种列就用高段值，否则报无定义。
- **源表坏值逐条修正并在测试里钉住**（HTML 合并单元格与扫描错字）。钢：HRC68 行缺 HRC 格；HRC28 被印成 18；HR15N(59)=9.2→90.2；HR30N(35)=51.8→54.8；HR45N(34)=25.9→35.8；HB(48)=401→461；不分钢种 σb(HRC30)=904→965；铬钢(45)=1488→1450（与碳钢同值）；铬镍钢(47)=4584→1584、(23)=8731→831、(38)=1132→1182；铬硅锰钢(47)=1673→1573；不锈钢(19)=77→737；HR15T(HRB61)=8.7→80.7。铝：HRF(HB125)=986→98.6；HV(HB132)=13.95→139.5；2A14 σb(HB138)=46→496；d(HB89)=7.714→3.714；HR30T(HB163/164)=78.0/78.4→75.9/76.1。铜：HR30T(HB112)=574→57.4；HR45T(HB128)=4.9→44.9；HR15T(HB120)=84.7→81.8、(HB178)=89.8→88.9；铍青铜棒材 σ0.01(HB176)=9→309；HR15N(HB212)=69.7→68.0；HR45N(HB318)=7→37.1；HV(HB344)=36.4→356.4；HRC(HB416)=4.8→46.8。修正依据是相邻行插值或明显少/多位，不改变表的整体走向。铬钼钢(39)=1246、HR45N(45)=49.9、铝 7A04 在 HB90～94 的小回摆、铜 HRB 在 HB202～206 的小回摆，都没有足够证据判为错值，保留原表值。
- **肖氏表是还原出来的**：原表是 6 组 (HS,HRC) 并排的多列排版，部分行合并错位。抽出所有对后按 HRC 排序；丢掉 3 个明显错位对，手工补回 6 个被合并单元格吞掉的对，得到 65 个节点，HRC 13～68 单调。HS 只属于钢族。

## 工程约定

- **改动只进 dev 工作区。** 先 `vulcan.dev.start`，在 F 盘工作区里改，`submit` 送审热装，批准后 `finish`。直接改主树最后没法 finish。
- **只用统一契约（宿主 6.0.0 起编译期强制）。** 宿主给的只有一条总线和一个上下文：`ExecuteAsync` / `InvokeAsync` / `RequestConfirmation`，登记口只能 `Register`。数据目录、运行方式走 `context.Environment`，宿主位置问 `vulcan.host.info`。不引用 `HistoryVulcan.Services`，不拼 `%AppData%`。✔
- **版本三处一致**：`<模块>Version.props`、`module.manifest.json`、`project.manifest.json`。不一致时宿主静默跳过整个模块。✔
- **`ModuleInfo.ModuleName` 显式写死模块名**：缺省值是程序集名，同时也是指令域。✔
- **页面 owner = `History` + 首字母大写的指令域**，与模块名无关；对不上整页被 Aurora 静默拒收。✔
- **界面协议指令**（`<域>.ui.describe / actions / data`）只读并带 `HiddenReason`。✔
- **宿主程序集 `Private=false`**：部署时由宿主提供；测试工程反过来 `Private=true`。
- **`.gitattributes` 必须有 `z-Publish/** binary`**：否则快照换行，finish 热装 SHA 不符。✔
- **`.ps1` 必须带 UTF-8 BOM**；`SHA256SUMS` 与 manifest 不能带 BOM。✔
- **模块内不定义 `[ComImport]`**：可卸载装载上下文不能做 COM 互操作。✔
- **不读已移除的上下文成员**（`context.Settings` / `context.DataDirectory`）。宿主日志用 `context.Log`，过程用 `CommandContext.Progress`。✔
- **不跨仓 ProjectReference**，文档里也不写指向别的仓的相对链接。✔
- **外部程序的 API 以真机标定为准。** 文档与实测不符时，把证据写进本文件，用测试钉住实测组合。
- 手写 JSON 用编辑工具整文件写，不要经 shell heredoc（反斜杠会被吃掉）。
